# Руководство по миграции и новым функциям

## Новые возможности

### 1. Множественные профили монтажа
- Пользователь может создавать несколько профилей монтажа
- Каждый профиль имеет свое название
- Можно установить профиль по умолчанию
- Профиль можно выбрать при создании/редактировании проекта

### 2. Выбор профиля для проекта
- При создании/редактировании проекта можно выбрать профиль монтажа
- Если профиль не выбран, используется профиль по умолчанию
- Смета рассчитывается на основе выбранного профиля

## Миграции Supabase

### Необходимые изменения в базе данных

Выполните SQL миграции из папки `supabase/migrations/`:

1. **001_add_missing_fields.sql** - добавляет:
   - `initial_quantity` (NUMERIC) в `materials`
   - `purchase_price` (NUMERIC) в `materials`
   - `total_cost` (NUMERIC) в `materials`
   - `profile_id` (UUID, FK) в `projects`
   - `is_default` (BOOLEAN) в `installation_profiles`

2. **002_update_sync_fields.sql** - защитная миграция для проверки полей

### Применение миграций

#### Через Supabase Dashboard:
1. Откройте Supabase Dashboard → SQL Editor
2. Скопируйте содержимое `001_add_missing_fields.sql`
3. Выполните запрос
4. Повторите для `002_update_sync_fields.sql`

#### Через Supabase CLI:
```bash
supabase db push
```

## Изменения в коде

### 1. Модели данных

**`src/services/storage/indexedDB.ts`:**
- `Project.profileId` - добавлено поле для связи с профилем
- `InstallationProfile.isDefault` - добавлено поле для профиля по умолчанию

### 2. Сервисы

**`profileService.ts`:**
- `getAllProfiles()` - получение всех профилей пользователя
- `createProfile(name, isDefault)` - создание профиля с опцией "по умолчанию"
- `updateProfile()` - обновление профиля (включая установку по умолчанию)
- `syncProfileToServer()` - синхронизация профилей с Supabase

**`projectsService.ts`:**
- Обновлена синхронизация для поддержки `profile_id`
- При синхронизации проверяется, является ли `profileId` UUID

**`estimateService.ts`:**
- Использует `project.profileId`, если указан
- Иначе использует профиль по умолчанию

### 3. UI компоненты

**`ProfilesList.tsx`:**
- Список всех профилей пользователя
- Выбор активного профиля
- Создание новых профилей
- Установка профиля по умолчанию
- Управление материалами и работами для выбранного профиля

**`ProjectEditor.tsx`:**
- Выбор профиля монтажа при создании/редактировании проекта
- Автоматический выбор профиля по умолчанию

## Синхронизация

### Обновленная логика синхронизации материалов

Теперь отправляются все поля:
- `initial_quantity` - изначальное количество
- `purchase_price` - стоимость закупа
- `total_cost` - общая себестоимость

### Обновленная логика синхронизации работ

- Исправлена проблема с `onConflict` для новых записей
- Используется `insert` для новых записей вместо `upsert` с несуществующим ограничением

## Откат изменений

Если нужно откатить изменения:

1. Удалите поля из Supabase:
```sql
ALTER TABLE materials DROP COLUMN IF EXISTS initial_quantity;
ALTER TABLE materials DROP COLUMN IF EXISTS purchase_price;
ALTER TABLE materials DROP COLUMN IF EXISTS total_cost;
ALTER TABLE projects DROP COLUMN IF EXISTS profile_id;
ALTER TABLE installation_profiles DROP COLUMN IF EXISTS is_default;
```

2. Откатите изменения в коде через git

## Примечания

- Профили синхронизируются с Supabase автоматически
- При установке нового профиля по умолчанию, старый автоматически снимается
- Если профиль не выбран для проекта, используется профиль по умолчанию пользователя
